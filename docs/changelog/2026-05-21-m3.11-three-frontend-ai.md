# M3.11 Three Frontend AI Assistants

Generated on 2026-05-21.

## Delivered

- Web owner assistant: `apps/web/src/app/chat-hub/page.tsx`
  - Four personas: serious advisor, warm steward, analyst, senior lawyer.
  - Message stream includes disclaimer, tier, confidence dots, and five owner next-step buttons.
  - File upload entry writes review intent into the chat input.
- Agent assistant: `apps/agent/src/app/assistant/page.tsx`
  - Role-specific "dispatch veteran" assistant.
  - Uses `agent.assistant_reply` and sends `role=steward` context.
  - Includes platform anti-bypass boundary.
- Gov assistant: `apps/gov/src/app/assistant/page.tsx`
  - Role-specific policy think tank assistant.
  - Uses `gov.policy_impact` and sends domestic-only context.
  - Backend `gov-domestic-only.guard.ts` enforces DeepSeek domestic route.
- Admin assistant: `apps/admin/src/app/assistant/page.tsx`
  - Role-specific operations advisor.
  - Covers BR red lines, anti-abuse tuning, customer-success SOP, credentials, and routing health.

## Dashboards

- Owner dashboard uses `apiClient.dashboard.owner()` and `GET /api/v1/dashboard/owner-kpi`.
- Agent dashboard uses `apiClient.dashboard.agent()`, `GET /api/v1/agent/reputation`, and `GET /api/v1/commissions/calendar`.
- Gov dashboard uses `apiClient.dashboard.gov()` and `GET /api/v1/dashboard/gov`.
- Admin dashboard uses `apiClient.dashboard.admin()` and `GET /api/v1/dashboard/admin`.

## Floating Bubble

- `AiAssistantBubble` now accepts `role=owner|steward|gov|admin`.
- Four app shells mount the role-specific bubble:
  - web: owner
  - agent: steward
  - gov: gov
  - admin: admin
