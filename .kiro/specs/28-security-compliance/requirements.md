## Requirements

### Requirement 1：审计日志体系（协议 P-2）

#### Acceptance Criteria

1. 审计字段：id / traceId / userId / tenantId / action / resource / before / after / ip / userAgent / createdAt
2. 永不删除（按月分区，6 年留存）
3. 政府版独立审计表（GovAuditLog）
4. 后台审计查询 + 导出

### Requirement 2：防薅 / 防黑（BR-315 完整实现）

#### Acceptance Criteria

1. **设备指纹**：浏览器 + 桌面 + 公众号
2. **黑名单**：手机号 / 营业执照 / 设备指纹（永久）
3. **行为风控**：
   - 同 IP + 同设备连续创建 ≥ 3 账号 → 标记
   - 智能管家自注册客户 / 关联智能管家手机号 → 拦截
   - 评分异常聚集（同 IP / 24h 内 ≥ 10 条 5★）→ 评分作废
   - 智能管家报价异常波动 → 告警
   - 客户年内退款 ≥ 3 次 → 限制
   - 邀请奖励异常（每用户每月 5 + 年 30 个上限）
4. 风控仪表盘（[`24-admin-console`]）
5. 异地登录 + 异常操作 → 二次验证

### Requirement 3：数据出境合规（BR-504 / BR-505）

详见 [`04-ai-gateway`]，本 spec 总审：
1. 全部出境调用必经 sanitizer
2. 用户级授权 + 协议 + checkbox
3. 政府版禁出境

### Requirement 4：数据脱敏

1. 输出脱敏（手机 / 身份证 / 银行卡 / 业主联系方式 / 合同金额）
2. 实现位置 [`security-rules.md` §5](../../steering/security-rules.md)

### Requirement 5：备份与灾备

#### Acceptance Criteria

1. 全量 pg_dump 每天 03:00 → OSS 跨区域复制（[`01-infra-monorepo`] F1）
2. 增量备份每小时
3. 30 天留存
4. 季度恢复演练（写 changelog）
5. RTO ≤ 4 小时 / RPO ≤ 1 小时（[`requirements.md` R9.2](../00-project-overview/requirements.md)）

### Requirement 6：紧急响应

#### Acceptance Criteria

1. 4 类紧急情况立即停服 + 通知用户：
   - 数据泄漏
   - 大规模越权
   - 模型供应商账号被盗
   - 资金异常出账
2. 流程：项目负责人 → 法务 → 客服 → 用户公告

### Requirement 7：合规自查

#### Acceptance Criteria

1. ICP 备案 + 用户协议 + 隐私政策 + 智能管家合作协议 + 数据出境授权书 5 项法律文件上线前完成
2. 季度自查
3. 年度合规审计

### Requirement 8：边界

1. 本 spec **不实现新业务**，仅集成 + 总审
2. 紧急响应流程为人工 + 系统协助（OPC 模式）

### Requirement 9：依赖

- 强依赖：所有模块
- 外部：法律顾问 / ICP 备案 / 阿里云 OSS

## V4 合规扩展（P4 / P8 补丁）

### Requirement 5：智能管家服务协议合规模块（V4 P4 补丁）

#### Acceptance Criteria

1. 智能管家注册时强制勾选 5 项合规承诺：
   - □ 承诺合规用工，不参与挂证 / 假社保
   - □ 承诺真实业绩，不参与作假
   - □ 承诺平台内交易，不绕单
   - □ 承诺保护客户隐私
   - □ 承诺接受信誉申诉裁决
2. 5 项承诺 = 协议核心条款，写入用户 `agent_consents` 表（永久留存）
3. 违反 = 立即清退 + 信誉一票否决 + 全网黑名单（手机 / 身份证 / 营业执照）
4. 后台可视化展示每个智能管家的承诺签订时间 + 版本

### Requirement 6：AI 数据源合规（V4 P4 补丁）

#### Acceptance Criteria

1. 同行情报：必须是公开数据源（中国招标投标公共服务平台 / 各省公共资源交易平台）
2. 业主资信深查：必须是公开数据源（信用中国 / 国家市场监督管理总局信用公示 / 中国裁判文书网）
3. 资质核验：四库一平台公开接口
4. SHALL NOT：爬非法源（未经授权的企业内部信息 / 非公开数据）
5. SHALL NOT：未经客户授权获取其在第三方平台的信息
6. 数据源清单维护在 [`20-knowledge-system`] 附录 A，定期审核更新

### Requirement 7：政企公文水印（V4 P4 补丁）

#### Acceptance Criteria

1. 所有政企版生成的公文 / 讲话稿 / 报告 / 项目申报材料：
   - 自动加"内部使用，不对外"水印（45° 倾斜，5% 透明度）
   - 含生成人姓名 + 时间戳 + 用户 IP（追溯）
   - PDF 末页含 traceId（可追溯完整生成路径）
2. 政府版 / 央国企版禁止 PDF "去水印"功能
3. 共享报告 / 转发 → 二维码追溯（点击可看生成元数据）

### Requirement 8：AI 输出免责强制（V4 P4 补丁，BR-322 升级）

#### Acceptance Criteria

1. 所有 AI 报告底部强制 4 要素 + 5 引导按钮（详见 BR-322）
2. 重大决策（合同 / 投资 / 法律意见）强制 Tier 边界
3. 涉及法律意见的输出不得用绝对化表述（详见 BR-323）
4. 数据源声明含具体来源（如"根据《中华人民共和国民法典》第 X 条"）
5. AI 输出违反任一项 → 自动拒绝并要求重新生成

### Requirement 9：项目寻源数据流约束（V4 P8 补丁）

#### Acceptance Criteria

1. 政企↔建筑企业项目寻源：
   - 政府发布项目脱敏摘要 → 推送匹配建筑企业
   - 建筑企业看到的脱敏摘要 SHALL NOT 包含具体单位 / 联系方式 / 金额精确值
   - 双向脱敏聊天通道 + 平台见证记录
2. 数据出境约束：
   - AI 生成项目寻源摘要 → **强制国产模型**（即使 BR-505 授权）
   - 双方聊天内容 → **强制国产模型** + 6 年留存
   - 项目寻源数据 SHALL NOT 出境（任何形式）
3. 双方接受合作 → 同时脱敏数据进审计日志
4. 任一方撤回意向 → 数据立即从对方系统隐藏（审计日志保留）
