# 21 规则引擎 + 参考价库 - Requirements

## Introduction

> 资质 / 合同风险 / 招标 三大规则库 + **市场参考价库**（落地 BR-310）。规则审核由专家在 [`24-admin-console`] 完成。
>
> 与 [`20-knowledge-system`] 的区别：知识库是**原文 + 摘要**；规则引擎是**结构化规则**（IF-THEN，可被业务代码直接执行）。

**前置依赖**：[`02`] / [`20-knowledge-system`]；后续被 [`13`] / [`14`] / [`22`] 消费。

---

## Glossary

| 术语 | 简要定义 |
|---|---|
| 规则 | 结构化 IF-THEN 表达（如"包含 '无限连带' → red 风险"）|
| 参考价库 | A 类派单服务的市场参考价（BR-310）|

---

## Requirements

### Requirement 1：资质规则库

#### Acceptance Criteria

1. 规则结构：资质类别 + 等级 + 升级要求（业绩 / 人员 / 设备 / 净资产）
2. 用于 [`14-qualification-guard`] 升级路径分析
3. 后台维护（增删改）+ 版本化

### Requirement 2：合同风险规则库

#### Acceptance Criteria

1. 规则结构：风险类型 + 触发条件（关键词 / 金额阈值 / 条款结构）+ 风险等级 + 修改建议 + 标准措辞
2. 用于 [`13-risk-review`] 合同审查
3. 6 大常见风险 + 50+ 起步规则（创始人 + 律师专家提供）

### Requirement 3：招标规则库

#### Acceptance Criteria

1. 规则结构：评分项 + 权重 + 常见陷阱 + 投标建议
2. 用于 [`12-tender-factory`] 评分预判 / 资格自查

### Requirement 4：市场参考价库（BR-310）

#### Acceptance Criteria

1. 服务类型：资质代办（按类别 / 等级）/ 标书代写（按金额段）/ 保函（按金额）等
2. 字段：参考价区间 + 数据来源（专家 / 历史成交）+ 更新日期
3. 业务消费：[`22-agent-workspace`] dispatch 模块的报价标色（绿 / 黄 / 红 / 超价 4 档）
4. 后台维护（专家 + 数据驱动）

### Requirement 5：规则审核台（在 [`24`] 实现 UI）

1. 待审核规则：原文（来自 [`20`]）+ AI 抽取规则 + 置信度
2. 专家通过 → 进生产规则库

### Requirement 6：规则版本化

1. 每条规则有版本号
2. 规则变更通过 ADR 流程（重大变更）
3. 历史版本可回滚

### Requirement 7：边界

1. SHALL NOT 自动发布未审核规则（防 AI 抽取错误污染）
2. SHALL NOT 实现复杂规则编排（仅 IF-THEN，复杂逻辑在业务代码）

### Requirement 8：依赖

- 强依赖：[`02`] / [`20`]
- 弱依赖：[`24`]
- 后续阻塞：[`13`] / [`14`] / [`12`] / [`22`]
