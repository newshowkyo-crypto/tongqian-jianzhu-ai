# 26 上瘾系统 - Requirements

## Introduction

> 功能区 O：9 大上瘾机制（BR-601 至 BR-604）。**克制使用**（[`ui-visual-spec.md` §8.3](../../steering/ui-visual-spec.md)），不浮夸。
>
> 9 大机制：① 每日签到累积 / ② 今日机会卡 / 风险红灯 / ③ 建筑能力等级 LV1-5 / ④ 限时抽点 / ⑤ 分享解锁 / ⑥ 月度经营成长报告 / ⑦ AI 老板助理养成系 / ⑧ 节点式紧迫感推送 / ⑨ 公众号每日内容矩阵

**前置依赖**：[`02`] / [`06`] / [`08`] / [`25`]；后续与 [`27`] 推送强协作。

## Requirements

### Requirement 1：每日签到（BR-602）

#### Acceptance Criteria

1. 连续签到 7 / 14 / 30 / 90 天解锁不同奖励（点数 + 实物 + 等级勋章）
2. 断签重新累积
3. 签到金币掉落动画 ≤ 600ms（[`ui-visual-spec.md` §8.3](../../steering/ui-visual-spec.md)）

### Requirement 2：今日机会卡 / 风险红灯

#### Acceptance Criteria

1. 首页固定区：今日推送的机会（来自 [`11`]）+ 今日风险（[`13`] / [`14`] 到期）
2. 上限：机会 ≤ 5 / 日；风险 ≤ 3 / 日（BR-604）

### Requirement 3：建筑能力等级 LV1-5

> ⚠️ **命名警告**：本 spec 的"建筑能力等级"是**客户企业**对 AI 工具使用的熟练度（owner 视角），**与 [`22-agent-workspace` 智能管家信誉等级 LV1-5](../22-agent-workspace/requirements.md) 是两个完全独立的概念**。
> - 智能管家 LV1-5（reputation_scores.entity_type='agent'）：派单匹配权重 + 推荐费上限 + 提现速度
> - 建筑能力 LV1-5（building_levels）：仅客户企业内部使用熟练度展示，不影响商业行为

> 实施：用不同表（`building_levels` vs `reputation_scores`）+ 不同 enum 命名（`BuildingLevel` vs `AgentReputationLevel`）防混淆。

#### Acceptance Criteria

1. 累积值：用 AI 任务次数 / 完成报告 / 上传业绩 / 完成签到 等
2. 等级解锁：LV1-5 各有解锁特权（如 LV3 解锁联合品牌报告）
3. 等级展示在企业首页 + 报告封面
4. 数据表：`building_levels`（详见 design.md）；**SHALL NOT** 复用 [`22`] 的 `reputation_scores`

### Requirement 4：限时抽点（BR-603）

#### Acceptance Criteria

1. 仅每周二 + 周五各 1 次
2. 转盘动画 800ms（标准物理曲线）
3. 奖品池：500-5000 点 + 实物礼券

### Requirement 5：分享解锁

#### Acceptance Criteria

1. 客户分享某报告 → 解锁高级模板 / 额外点数
2. 客户邀请客户 → 200 点 + 10% 红包（详见 [`22`] BR-301）

### Requirement 6：月度经营成长报告

#### Acceptance Criteria

1. 月初 1 号生成上月报告：业绩 / 机会捕获率 / 资质健康度 / 风险事件 / 同行对标 5 维
2. H5 形式（≤ 3 屏）
3. 鼓励性 AI 文案 + 来自杀手锏数据

### Requirement 7：AI 老板助理养成系

#### Acceptance Criteria

1. 老板助理（[`15`] / [`25`]）有"成熟度"（基于客户使用次数 + 数据完整度）
2. 越熟越懂业务（提示更精准）
3. 视觉：助理头像随成熟度变化（实习 → 资深 → 总监）

### Requirement 8：节点式紧迫感推送（BR-604）

#### Acceptance Criteria

1. 资质到期 / 招标截止 / 项目机会即将下架 等
2. 推送频率上限 3 条 / 日
3. 消息合并优先级（最紧迫优先）

### Requirement 9：公众号每日内容矩阵

#### Acceptance Criteria

1. 每日 8 类公众号文章封面模板（创始人 / 运营运营）
2. 公众号 → 智能管家朋友圈 → 客户首页 三级矩阵

### Requirement 10：边界

1. SHALL NOT 做"无限连签"奖励（断签不可恢复）
2. SHALL NOT 24h 不停推送（疲劳）
3. SHALL NOT 在政府版（apps/gov）开启上瘾机制

### Requirement 11：依赖

- 强依赖：[`02`] / [`06`] / [`08`] / [`25`]
- 弱依赖：[`27`] / [`11`] / [`13`] / [`14`]

## V4 升级：上瘾机制重审 + 钩子 16 个 + 输出红线（V4 核心）

> **V4 决策**：经创始人审视，9 大机制扩展为 **16 个真粘性钩子**（一期 13 + 二期 7 - 1 重复 = 16），按价值密度自检表（[AGENTS.md §3.8](../../../AGENTS.md)）每个必过 6 题。
> **核心原则**：钩子 = 创造价值，不是消耗点数。每个钩子若是付费看的内容，客户必须满意。

### Requirement 12：16 个粘性钩子分组（V4）

#### A. 每天必看 · 信息焦虑（3 个）

12.1 **老板早报 7:30**（50 点 / 天）
- 90 秒读完 5 条干货：政策 / 机会 / 风险 / 同行 / 数据
- 个性化（含老板姓 + 公司名 + 本省数据）
- 月度按档限免：trial 5 天 / ¥39 档 20 天 / ¥199 档工作日不限 / ¥499+ 不限
- 输出红线：每条 ≥ 30 字（含数字 + 时间 + 来源）+ SHALL NOT 全是套话

12.2 **行业宏观仪表盘**（含点数）
- 建筑业 PMI / 央企新签 / 本省项目热力图 / 钢材水泥价
- 数据每日更新

12.3 **政策快报闪现**（实时推送）
- 新政 5 分钟内推送 + 本企业红绿灯影响
- 触发：[`20`] 政策抓取命中关键词

#### B. 每天必玩 · 实用钩子（4 个）

12.4 **今日机会卡 / 风险红灯**（含点数）
- 已有，来源 [`11`] / [`13`] / [`14`]

12.5 **每日招标盲盒**（含点数）
- 5 个匹配项目 + 一键开盒看 AI 评分 + 一键投标
- 来源 [`11`] 机会雷达数据

12.6 **标书员每日真题**（50 点 / 题，每天 1 题免）
- 1 题 = 1 个真实案例（来自规则库 / 案例库 / 历史合同纠纷）
- 4 选项必须有迷惑性
- AI 详解必须含：法律 / 行业惯例 / 失败案例 / 建议
- 第 2 题起扣 50 点

12.7 **金句日历**（30 点 / 天 / 主动调，自动推送 0 点）
- 每天 1 句行业金句 + 自动配老板姓名 + 配图 + 一键转发

#### C. 每周必到 · 钱包钩子（2 个）

12.8 **本省同行 PK 排行**（500 点 / 月度查询）
- 资质健康度 / 投标命中率 / 营收同比
- 匿名 + 显名两版本（旗舰版可看显名）

12.9 **限时惊喜抽点**（已有，BR-603）
- 每周二 + 周五各 1 次
- 转盘动画 800ms

#### D. 每月必参 · 沉淀钩子（2 个）

12.10 **月度经营成长报告**（已有 R6）
- 5 维 H5 报告

12.11 **建筑能力等级 LV1-5**（已有 R3）
- 给员工，与智能管家信誉分独立

#### E. 沉默触点（2 个）

12.12 **公众号每日内容矩阵**（已有 R9）

12.13 **节点式紧迫感推送**（已有 R8，BR-604）
- 上限 3 条 / 日

#### F. 智能管家专属（3 个）

12.14 **收益日历 S1**（每天 0:00 短信）
- "昨日 ¥XXX 已入账"
- 多巴胺打卡

12.15 **客户健康度仪表 S2**（每天）
- 智能管家工作台首页：客户 LV / 续费倒计时 / 该联系谁
- 与 [`22`] R10 客户预警卡协同

12.16 **案例市场 S3**（UGC）
- 详见 [`22`] R11

### Requirement 13：钩子输出价值标杆（V4 BR-325 红线 3）

#### Acceptance Criteria

每个钩子的输出必须满足以下红线，否则 SHALL NOT 上线：

1. **早安简报**：≥ 5 条干货 + 个性化 + 含数字 / 时间 / 来源 + SHALL NOT 套话广告
2. **决策小测**：1 题 = 1 真实案例 + 4 迷惑选项 + AI 详解（法律 + 案例 + 建议）
3. **同行情报**：基于真实数据（中标公告 / 招投标 / 四库一平台）+ 可一键深查 + ≤ 3 条 / 天
4. **AI 周报**：含本租户真实数据 + ≥ 5 个 KPI + 3 个待办 + 2 个建议 + 环比对比
5. **公文代写**：符合党政机关 / 商务格式规范 + 可直接打印盖章 + 完整要素
6. **灵感卡**：基于本周本地真实情报 + 1 张卡 = 1 条情报 + 1 个动作建议 + SHALL NOT 推广 / 鸡汤

### Requirement 15：奖励发放清算流程（V4 P6 补丁）

#### Acceptance Criteria

#### R15.1 三层清算策略

1. **点数奖励（如 +100 点）**：
   - 实时入账，写 `user_credits.gift_credits` 字段
   - 90 天有效期（防囤）
   - 无需对账（系统内部）

2. **实物奖励（如笔记本 / 段位牌）**：
   - 中奖后系统弹窗"请提供收货地址"
   - 客户成功在 admin 后台确认地址 → 平台采购 → 物流跟踪
   - 月度对账（采购 / 物流 / 损耗）
   - 客户签收 = 完成

3. **现金红包 / 大奖（≥ ¥800）**：
   - 触发：年度盲盒 / 大额抽奖
   - 中奖 → 国税局个人偶然所得 20% 代扣（合规）
   - 客户成功在 admin 后台审批 + PLATFORM_OWNER 双签
   - 财务通过对公转账打款（**SHALL NOT** 走微信红包，避税）
   - 与 [`09-payment-gateway`] R10 协同

#### R15.2 防作弊

1. 同手机 / 设备 / IP 频繁中奖 → 风控审核
2. 异常领奖（短期大量）→ 自动冻结 + 风控
3. 邀请奖励上限：每用户每月 5 个 + 年累计 30 个

### Requirement 16：政企不参与游戏化

1. 政企版（apps/gov）SHALL NOT 启用：抽点 / 真题 / PK 榜 / 朋友圈 / 段位 / 实物奖励
2. 政企版仅启用：要情简报（每日，等价于 12.1 老板早报但内容政务化）/ 政策快报（12.3）/ 月度工作小结（12.10 改名）/ 紧迫感推送（12.13，资金申报截止）
3. 合规优先 > 粘性

## V4 IMPROVEMENTS · Onboarding 用户旅程（漏洞 2 修补）

### Requirement 17：客户首单 Onboarding（5 触点）

#### Acceptance Criteria

#### R17.1 注册当天 / Day 1（必触达）

- 注册成功立即推送 1 条欢迎短信 + 1 条站内信
- 站内信含"5 步走完激活"清单：
  1. 完善企业信息（资质 / 业绩 / 联系人）
  2. 跟 AI 助理说一句话
  3. 上传一份合同或招标文件试试
  4. 关注地区 / 业务线 / 金额区间
  5. 加智能管家好友（如有归属）
- 完成 5 步 → 解锁 100 点奖励 + 进入"激活态"

#### R17.2 Day 1 当天

- 7:30 自动推送早安简报（含老板姓 + 公司名）
- 客户首屏 banner："欢迎张总，AI 老板助理已就绪 →"

#### R17.3 Day 3-7 第 1 周

- AI 助理主动发起对话（系统检测到 ≥ 24h 未对话）：
  - "张总，我看到您还没用过合同审查功能，要不要试试？只要 30 秒就能给您出一份风险卡。"
- 推送 1 个"今日机会卡"+ 1 个"风险红灯"
- 推送智能管家 / 客服联系方式（如有归属）

#### R17.4 Day 7-30 第 1 月

- 第 7 / 14 / 21 / 28 天分别推送 1 条"功能引导":
  - D7：早安简报 / 决策小测
  - D14：标书工厂 / 资质管家
  - D21：财务 / 现金流 / 催收
  - D28：月度经营成长报告（首份）
- D30 自动生成首份"月度经营成长报告"（即使数据稀疏，也用合成场景填充）

#### R17.5 防 Onboarding 失败

如检测到客户 D7 未触达 ≥ 1 次 AI 调用 → 客户成功（CSM）24h 内手动介入：
- 站内信 + 短信
- D14 仍未激活 → 电话回访
- D30 仍未激活 → 标记"流失风险"，进入挽回名单
