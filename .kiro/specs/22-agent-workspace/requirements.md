## Requirements

### Requirement 1：智能管家工作台首页（核心模块）

#### Acceptance Criteria

1. 看板：今日朋友圈日报 / 信誉分 + 等级 / 收益（冻结 / 可结算 / 推荐费）/ 待接派单 / 我的客户
2. 等级显示：LV1-5 + 信誉分 + 距下一级所需分数 + 本月加减分明细 + 申诉入口
3. 月度排行榜（按分润 / 信誉分 双维度）

### Requirement 2：三层裂变（BR-301）

#### Acceptance Criteria

1. **智能管家→客户**：推广码 + 链接 + 二维码（永久绑定 BR-102）
2. **智能管家→智能管家**：邀请新智能管家加盟，新智能管家所有分润 10% 永久同步给老智能管家；新智能管家首笔 ¥1000 → 老智能管家一次性 ¥200（BR-305）
3. **客户→客户**：客户邀请客户 → 200 点 + 10% 红包
4. SHALL NOT 三级及以上（CI 检查 agent_relations 自引用层级 ≤ 2）

### Requirement 3：分润计算（BR-302 / BR-303 / BR-304）

#### Acceptance Criteria

1. 订阅分润：首年 30% / 次年 20%
2. 充值流水分润：15%
3. 派单 0 抽成 + 跨域 5% 代扣代付（详见 [`09`]）
4. 状态机 frozen → settlable → withdrawable → paid

### Requirement 4：朋友圈日报（裂变素材）

#### Acceptance Criteria

1. 每日 08:00 自动生成 H5 卡片 + 文案（≤ 100 字）
2. 基于当日热点 + 智能管家所在地区
3. 一键转发（分享到微信）

### Requirement 5：派单大厅（BR-307 至 BR-316）

详见 [`design-flows.md` §7](../00-project-overview/design-flows.md) 完整时序图。

#### Acceptance Criteria

1. **需求分类**（BR-307）：A/B/C 三类，C 自动升级 B
2. **池路由**（BR-308）：归属 → 跨域池 → 公开池 → 抢单 1h → 客服兜底
3. **4 维加权**（BR-336）：地区 + 子类 + 智能管家等级 + 月度满意度
4. **报价标色**（BR-310）：调 [`21`] RefPrice → 绿 / 黄 / 红 / 超价
5. **客户最终选定**（BR-310 客户端订单页）：客户从所有候选智能管家中**自主选择**（基于报价 + 信誉 + 评分摘要），平台不强制按评分排序成交
6. **同乾方略接管**（BR-311）：6 触发 + 推荐费按触发原因区分（100% / 80% / 0%）
7. **双向评分**（BR-312）：客户必填 + 智能管家选填 + 30 天窗口 + 自动 4★ + 防骚扰（每订单 ≤ 1 次催评）
8. **推荐费**（BR-313）：按类型冻结期 7/30/45 天 + LV3 以下封顶 10%
9. **申诉**（BR-314 / BR-335）：客服 24h → 风控 72h → 客户成功仲裁 7 天 + 终审不可申诉

### Requirement 6：信誉机制（BR-331 至 BR-336）

详见 [`design-flows.md` §8](../00-project-overview/design-flows.md) 事件溯源。

#### Acceptance Criteria

1. **智能管家信誉分**（BR-331）：0-1000，基础 500，加减分项明细见 [`design-flows.md` §8.2](../00-project-overview/design-flows.md)
2. **5 级等级**（BR-332）：LV1-LV5 + 新智能管家 30 天保护 + LV1 重启计划（试水订单上限 ¥3000，终身 6 次）
3. **客户信誉分**（BR-333）：挂 tenant 维度，企业内用户行为聚合
4. **公开度**（BR-334）：智能管家信誉对客户公开；客户信誉仅接单智能管家可见
5. **申诉**（BR-335）：reputation_logs 7 天申诉窗口 + 反向事件回滚（不删原 log）
6. **派单联动**（BR-336）：等级权重 LV5 +20 / LV4 +15 / LV3 +10 / LV2 +5 / LV1 +1

### Requirement 7：客户管理

#### Acceptance Criteria

1. 我的客户列表（按归属，BR-102 永久绑定）
2. 每个客户显示信誉分（仅接单智能管家可见，BR-334）
3. 信誉 < 300 → 强制智能管家报价含 30% 预付款条款（BR-333）

### Requirement 8：高端服务货架（BR-316）

#### Acceptance Criteria

1. 10 类 B 类高端服务（化债 / ABS / REITs / SPV / 央国企融资 / 重大陪标 / 资质一级特级 / 政府专项债 / PPP / 跨境）
2. 智能管家可一键将客户推荐到货架 → 归属永久绑定 → 拿推荐费

### Requirement 9：联合品牌报告（BR）

1. ¥499+ 客户由智能管家推荐 → 报告署名"由 {智能管家公司} 联合 同乾方略 AI 出品"

### Requirement 10：智能管家职责定义 + AI 客户预警卡（V4 新增 P3 补丁）

#### Acceptance Criteria

1. **智能管家职责严格限定**（BR-325 红线 2）：
   - SHALL：跑住建局窗口排队 / 提交纸质材料 / 现场答辩
   - SHALL：联系业主 / 评审 / 政府关系
   - SHALL：替客户处理材料齐备 / 现场答辩 / 应急
   - SHALL：失败赔付 + 临时调度备用方案
   - SHALL NOT：解读 AI 报告给客户听（AI 已出可执行方案）
   - SHALL NOT：替代 AI 给方案
   - SHALL NOT：以"AI 看不懂 / 不够"为由收咨询费

2. **AI 客户预警卡（智能管家工作台首页固定位）**：
   - 数据信号库（每天扫一次）：
     · 客户上传招标文件 → 投标需求信号
     · 客户资质快到期 < 60 天 → 续证需求
     · 客户应收异常 ≥ 90 天 → 催收需求
     · 客户投标失败 → 调标需求
     · 客户业绩录入 → 升级机会
     · 客户长期不活跃（30 天）→ 流失风险
   - 预警卡 UI（每张卡含）：
     · 客户头像 + 信誉分 + 等级
     · 信号类型 + 紧迫度（红黄绿）
     · 距离时间窗（如"距 11/30 还 14 天"）
     · 一键操作：[一键发起服务] [发短信邀约] [关闭今日推送]
   - 行为约束：
     · 智能管家"一键发起服务" → 系统记录 + 7 天内不重复推送
     · 客户拒绝 → 标记 + 3 月内不重复
     · 主动联系成功率纳入信誉分（积极性加分 +5 / 单成单）

3. **客户档案库**（每个归属客户一个完整档案）：
   - 全部证书 OCR + 续期日历
   - 关键人员（建造师 / 安全员 / 八大员）
   - 业绩库（项目类型 / 金额 / 业主）
   - 社保连续性核验状态
   - 资质动态核查记录
   - 历史升级路径
   - 7 天内 AI 方案查询窗口（看到归属客户最近的 AI 方案，主动联系切入）

### Requirement 11：案例市场 UGC（V4 新增 P7 补丁）

#### Acceptance Criteria

1. 智能管家上传成功案例（脱敏）→ 通过审核 → 平台案例库
2. **3 道审核机制**：
   - 自审：上传时强制勾选 3 项承诺（已脱敏 / 真实 / 接受平台审核）
   - 机器审：AI 自动检测客户姓名 / 公司名 / 联系方式残留 → 自动打码 + 重复 / 抄袭 / 违规自动拒绝
   - 专家审：同乾方略团队周一三五各 1h 审，通过 +50 点，优质（专家点赞）+200 点 + 信誉 +30
3. 他人下载案例 → 上传方分润 5 点 / 次（UGC 沉淀机制）
4. 优质案例标注 + 公开排行榜

#### V4 IMPROVEMENTS 抄袭检测细化（漏洞 7 修补）

5. **AI 自动检测语义相似度**：
   - 与现有案例库对比，相似度 ≥ 0.85 视为抄袭 → 自动拒绝
   - 相似度 0.70-0.85 → 标记可疑 → 专家人工审
   - 使用 sentence-embedding（与 29-prompt-testing 相同 embedding 模型）

6. **重复上传同一案例**：
   - 30 天内同一智能管家上传相似案例（≥ 0.85）→ 拒绝 + 警告
   - 90 天内重复 ≥ 3 次 → 信誉 -30

7. **自买刷量检测**：
   - 智能管家自己 / 关联账号下载自己案例 → 不计入分润
   - 同 IP / 设备指纹下载同一智能管家案例 ≥ 5 次 / 月 → 风控审核
   - 异常下载（短期大量）→ 自动冻结 + 风控

8. **案例水印**：
   - 案例下载 PDF 含下载方姓名 + 平台 traceId
   - 防止下载方再分发

### Requirement 12：防黑（BR-315 部分实现，[`28`] 全面）

1. 同手机 / 设备 / IP 检测多账号 + 自注册检测
2. 报价异常波动告警
3. 评分异常聚集告警
4. 检测客户 AI 助理对话提及"加微信""线下交易" → 弹窗提醒
5. 智能管家月外联次数 ≤ 5 次 / 月（防绕单）
6. 智能管家私接 B 类业务被发现 → 扣信誉 -300 + 黑名单（终身封禁）

### Requirement 13：边界

1. SHALL NOT 实现完整 CRM（仅本平台客户）
2. SHALL NOT 自动决策派单（4 维加权排序，最终客户选）
3. SHALL NOT 提供"挂证撮合"功能（合规红线，详见 [`14-qualification-guard`]）
4. SHALL NOT 让智能管家做"AI 方案的解读员"（BR-325 红线 2）

## V4 IMPROVEMENTS · 智能管家代理人 PARTNER（二期 M4 启用）

### Requirement 15：PARTNER 角色（V4 IMPROVEMENTS 决策 1）

#### Acceptance Criteria

#### R15.1 注册与定位

1. PARTNER 是 AgentSubtype 的第 5 个值（其他 4 个：QUAL / TENDER / FIN / GENERAL）
2. PARTNER 注册要求：
   - 实名 + 简历认证
   - 反薅 5 维去重（同 BR-315）
   - 合规承诺勾选（同 28-spec R5）
   - **不强制 6 节培训**（接单类必培训，PARTNER 不接单不培训）
3. PARTNER 状态机：pending_review → active（审核通过即可，无 training 阶段）
4. PARTNER SHALL NOT 接派单（工作台无派单大厅按钮）

#### R15.2 PARTNER 推荐能力

1. **推荐建筑老板**：通过推广码 + 链接 + 朋友圈卡片
2. **推荐其他智能管家**（含 PARTNER）：通过邀请码
3. **推荐高端客户给同乾方略**：通过工作台"高端服务货架"一键推荐

#### R15.3 PARTNER 分润规则（与 BR-302/305/313 自洽）

| 推荐对象 | PARTNER 拿什么 | 不冲突原因 |
|---|---|---|
| 推荐建筑老板首年订阅 | **5% 永久** | 接单归属智能管家拿 30%（BR-302 不变），平台净拿 65% 而非 70% |
| 推荐建筑老板充值流水 | **3% 永久** | 接单归属智能管家拿 15%（BR-302 不变），平台净拿 82% 而非 85% |
| 推荐其他智能管家加盟 | **永久 5% + 首笔 ¥100 一次性** | 接单类老智能管家推荐拿 10% / ¥200（BR-305），PARTNER 因为不投入培训所以减半 |
| 推荐高端客户给同乾方略（B 类）| **5% 推荐费** | 归属智能管家拿 10-15%（BR-313），PARTNER 因为不是归属所以减半 |

#### R15.4 PARTNER 反作弊（强约束）

1. PARTNER 推荐的客户在 30 天内必须有真实付费 / AI 调用 ≥ 100 点 → 否则推荐失效
2. 一年最多推荐 50 个老板 + 20 个智能管家
3. 同手机 / 同 IP / 同设备指纹被推荐 → 自动拒绝（与 BR-315 一致）
4. PARTNER → PARTNER 二级封顶（不允许三级链）
5. PARTNER 自身被举报刷量 ≥ 3 次 → 一票否决归零封号

#### R15.5 PARTNER 信誉分（独立计算）

不复用接单类信誉分（BR-331）。PARTNER 信誉维度：
- 推荐成功率（≥ 30% +20 / 月）
- 推荐客户活跃度（月活 ≥ 50% +30）
- 推荐客户付费率（≥ 20% +50）
- 客户投诉（每条 -50）
- 刷量被发现（一票否决）

#### R15.6 工作台 UI（apps/agent 专属页面）

- 推荐链查看（最近 90 天 / 全部）
- 分润流水（推荐者分润 + 大单推荐费）
- 推广码 / 邀请码 / 朋友圈卡片
- 客户分润状态（哪些客户已激活 / 未激活 / 失效）
- SHALL NOT 显示派单大厅 / 客户预警卡（接单类专属）

#### R15.7 一期 / 二期分期

- **一期 M1-M3**：仅 4 接单子类型，PARTNER 不开放
- **二期 M4 起**：邀请制内测 50 PARTNER（创始人手动审）
- **三期 M7 起**：完全开放

## V4 IMPROVEMENTS · 私下交易反作弊（漏洞 5 修补）

### Requirement 17：私下交易 / 红包 / 礼物反作弊

#### Acceptance Criteria

#### R17.1 客户评分关键字检测

- 客户评分 / 评论中如出现"红包 / 礼物 / 私下 / 加微信 / 转账 / 现金"关键字
- 自动告警（不公开提示客户）→ 风控审核
- 风控认定为私下交易 → 智能管家信誉 -50 + 1 个月限派单 + 写审计

#### R17.2 智能管家月外联次数限制

- 智能管家通过站内信向客户发送外部联系方式（电话 / 微信 / 邮箱等）
- 限额 ≤ 5 次 / 月（默认值，admin 后台可调）
- 超限 → 自动屏蔽 + 告警

#### R17.3 客户 / 智能管家私下交易黑名单

- 风控认定的私下交易：建立黑名单库
  - 智能管家被列入 → 终身封禁
  - 客户被列入 → 限制后续派单（仅可走客服分配）
- 黑名单跨域共享（防换号绕过）

#### R17.4 举报通道（双向）

- 客户工作台 / 智能管家工作台均有"举报"按钮
- 举报理由 6 类：私下要红包 / 索要礼物 / 私下交易 / 故意拖延 / 服务质量差 / 其他
- 举报立即进入风控队列（24-72h 处理）
- 举报成立 → 双方任一方违规 → 信誉 -50 / -100 + 派单限制

#### R17.5 系统主动检测

- AI 助理对话中检测"加微信 / 线下 / 红包 / 礼物" → 自动弹窗提醒"平台保护您的权益，建议在平台内派单"
- 频率：同一客户每月最多弹窗 3 次（防过度打扰）
- 弹窗后客户仍要求线下 → 标记 + 风控审核
