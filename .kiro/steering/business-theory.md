## 一、营销专家视角（AARRR + LTV + K 系数 + NPS）

### 1.1 AARRR 转化漏斗（每个阶段的具体战术）

```
Acquisition 获客
  → 公众号文章 + 智能管家朋友圈卡片 + 同行 PK 显名榜 + 客户邀请码
  → CAC 目标 ≤ ¥110

Activation 激活
  → 注册即送 500 点 + 周签到 50 点（互惠原则）
  → 老板早报 7:30 自动推送（让用户第 1 天就收到价值）
  → 智能管家审核通过即推 6 节培训
  → 激活率目标 ≥ 70%

Retention 留存
  → 16 个上瘾钩子分日 / 周 / 月布局
  → 风险红灯 + 招标盲盒 + 灵感卡 多触点
  → AI 助理养成系（连续 7/30/100/365 天解锁）
  → 月度经营成长报告
  → 月留存率 ≥ 88%（年流失 ≤ 12% BR-901 红线）

Revenue 营收
  → 5 档订阅（39 / 199 / 499 / 999）+ 加购点数包
  → ¥199 档点数月底必然不够 → 引导加购或升档
  → 阶梯优惠（连续 3/6/12 月 8.5/8/7 折）锁定长期付费
  → 同乾方略接管 = 高单价咨询转化（5%-7%）
  → LTV / CAC ≥ 25x

Referral 转介绍
  → 智能管家 → 客户：30/20/15% 三档分润
  → 智能管家 → 智能管家：永久 10% + 首笔 ¥200 一次性
  → 客户 → 客户：200 点 + 10% 红包
  → K 系数目标 ≥ 1.5（自传播）
```

### 1.2 客户 LTV 最大化（V4 校准）

```
LTV 公式：
  LTV = ARPU × 平均存活期 × 毛利率 + 转介绍价值

V4 目标：
  ARPU ≥ ¥159 / 月（5 档加权）
  存活期 ≥ 15 个月（月留存 ≥ 88%）
  毛利率 ≥ 23%（含 AI 成本 + 智能管家分润 + 通道费）
  → LTV ≥ ¥2,794

V4 提升路径：
  1. 早安简报 + 钩子组合让月度活跃度 ≥ 85%
  2. ¥199 档点数不够 → 引导加购（点数毛利 70-87%）
  3. ¥499+ 解锁项目部 / 应收 / 联合品牌（升档动力）
  4. 同乾方略 5% 转化 → 推荐费回流智能管家 → 智能管家更卖力
  5. 阶梯优惠绑定 12 月以上长期付费
```

### 1.3 K 系数（病毒传播）

```
K = i × c
  i = 每个用户邀请人数
  c = 邀请转化率

平台设计：
  智能管家邀请客户：i ≥ 5（朋友圈 + 推广码）× c ≥ 30% → K ≥ 1.5
  老带新（同行邀请）：i ≥ 2（邀请码红包）× c ≥ 25% → K ≥ 0.5
  智能管家邀请智能管家：i ≥ 3（永久 10%）× c ≥ 30% → K ≥ 0.9
  
  综合 K ≥ 1.5 即自传播（K > 1 = 病毒增长）
```

### 1.4 NPS 净推荐值（月度跟踪）

```
NPS 调查触发：
  • 首单完成后 + 7 天
  • 月度活跃用户随机 10%
  • 服务订单完成后强制（智能管家服务 / 同乾方略咨询）

NPS 分层：
  推荐者（9-10 分）→ 触发"邀请同行"奖励
  中立者（7-8 分）→ AI 后续主动跟进
  贬损者（≤ 6 分）→ 客户成功 24h 内电话回访 + 风险标记

V4 目标：NPS ≥ 50（行业优秀 ≥ 30）
```

## 二、说服学专家视角（Cialdini 6 原则 + UX 心理学）

### 2.1 Cialdini 6 大说服原则

#### 1. 互惠（Reciprocity）

```
体现位置：
  • 注册即送 500 点 + 周签到 50 点（先给）
  • 早安简报每天免费（持续给）
  • 决策小测每天 1 题免（持续给）
  • 客户连续付费 3 月 → 触发"贵宾礼包"

实现红线：
  SHALL：先给价值再要求付费
  SHALL NOT：免费内容打折（V4 红线 1）
```

#### 2. 承诺一致（Commitment / Consistency）

```
体现位置：
  • 注册时勾选"我同意"系列（5 项合规承诺 / 数据出境授权）
  • 智能管家审核通过 → 强制 6 节培训通关（强化承诺）
  • 客户首次付费 → 自动开启"经营管家计划"（顺势开启自动续费）
  • 阶梯优惠"连续 3/6/12 月 8.5/8/7 折"诱导长期承诺

实现红线：
  SHALL：每次"同意"明示具体条款
  SHALL NOT：诱导用户做与本意冲突的承诺
```

#### 3. 社会认同（Social Proof）

```
体现位置：
  • 老板首页"本省同行已签约 X 家建筑企业"
  • 智能管家工作台"金牌智能管家俱乐部 X 人"
  • 政企版"全国 X 家政府单位已使用同乾方略"
  • 公众号案例："武汉 XX 公司用同乾方略 3 月签下 ¥1.2 亿订单"

实现红线：
  SHALL：所有数据真实可核
  SHALL NOT：捏造 / 夸大 / 假证言
```

#### 4. 喜好（Liking）

```
体现位置：
  • 智能管家头像 + 公司 LOGO（人设温暖）
  • AI 助理 4 种性格（让客户选喜欢的）
  • 老板早报含老板姓 + 公司名（个性化）
  • 灵感卡用老板风格写文案
  • 月度报告"张总你好"开头

实现红线：
  SHALL：保持品牌一致性（Source Han Serif + 深蓝玫瑰金）
  SHALL NOT：滥用情感操纵
```

#### 5. 权威（Authority）

```
体现位置：
  • 同乾方略品牌（建筑业高端咨询公司）
  • 智能管家 LV4+ 金牌徽章
  • 报告署名"由 同乾方略 联合 {智能管家公司} 出品"
  • 数据源声明（"根据《XX 法》第 X 条"+"住建部最新政策"）
  • 同乾方略团队顾问头像 + 资历

实现红线：
  SHALL：数据源真实可核
  SHALL NOT：伪造资历 / 案例 / 引用
```

#### 6. 稀缺（Scarcity）

```
体现位置：
  • "本月 LV5 首席管家仅 50 名"
  • "限时抽点每周二 / 五各 1 次"
  • "招标盲盒今日仅 5 个机会"
  • "申报截止前 30 / 7 / 1 天倒计时"
  • "旗舰版专属顾问每位带客户 ≤ 30 个"

实现红线：
  SHALL：稀缺真实
  SHALL NOT：制造虚假紧迫感
```

### 2.2 UX 心理学（决策门槛设计）

```
3 秒抓眼球：首页 1 屏必有一个最强信息（今日机会卡 / 风险红灯）
5 秒决策：每个任务 5 秒读完（标题 + 1 行结论 + 一键操作）
30 秒首响应：AI 必出第一句话不超 30 秒
Hick's Law：选项越少决策越快
  → 5 引导按钮（不是 10 个）
  → 5 档订阅（不是 10 档）
  → 4 角色（不是 30+ 注册类型）
默认效应：自动续费默认开启（用户协议明示，可随时关闭）
锚定效应：PDF 显示"如外协律师要 ¥XXX"，对比 AI ¥X
框架效应："省 80% 时间" vs "贵 ¥199 / 月"
损失厌恶：紧迫推送（资质到期 / 招标截止）
```

### 2.3 防黑暗模式（Anti-Dark-Pattern）

```
SHALL NOT：
  • 故意藏取消订阅按钮
  • 默认勾选附加服务
  • 用 Confirm-Shaming（"确定不要这个优惠？"）羞辱用户
  • 假倒计时
  • 价格藏在小字里
  • 强制弹窗不可关
  • 钩子设计成"心理操纵"

SHALL：
  • 所有取消 / 退订 / 申诉路径明显可见
  • 价格清晰透明
  • 让用户随时关闭推送 / 钩子
  • 提供"我反感这种推送"反馈通道（NPS 贬损者倾向）
```

## 三、软件架构师视角（10 大架构原则）

### 3.1 12-Factor App（已在 ADR-001）

```
1. 代码库统一（Git monorepo）
2. 显式声明依赖（pnpm lockfile）
3. 配置外置（.env / system_configs）
4. 后端服务作为附加资源（PG / Redis / OSS）
5. 严格分离构建 / 发布 / 运行
6. 进程无状态（业务状态在 PG / Redis）
7. 端口绑定（每个服务暴露端口）
8. 并发（worker / 进程级 scale）
9. 易处置性（快速启动 / 优雅关闭）
10. 开发 / 生产对等（Docker Compose 一致）
11. 日志即数据流（pino + 阿里 SLS）
12. 管理后台进程（admin task / migration）
```

### 3.2 事件驱动架构（Event-Driven）

```
触发：BullMQ 队列 + Redis Streams

业务场景：
  • 客户付费成功 → 发出 PaymentSucceeded 事件
    → credit-service 增加点数
    → notification-service 发送站内信
    → analytics-service 记录漏斗
    → audit-service 写审计

  • 智能管家服务完成 → 发出 ServiceCompleted 事件
    → commission-service 进入冻结
    → reputation-service +5 信誉
    → notification-service 提醒客户评分

  • AI 任务完成 → 发出 AiTaskCompleted 事件
    → cost-meter 记成本
    → cache-service 写缓存
    → analytics-service 记延迟

跨服务通过事件解耦，不直接调用
```

### 3.3 CQRS（命令查询分离）

```
写模型：业务表（agent_profiles / contracts / reports）
读模型：副本（report_snapshots / analytics_views / dashboard_aggregates）

业务运营看板从读模型取（高并发场景必备）
RDS 主写从读 + Redis 缓存
```

### 3.4 微前端 / 模块联邦

```
4 个子前端独立部署：
  apps/web    建筑企业前台
  apps/agent  智能管家工作台
  apps/gov    政企版
  apps/admin  平台后台

共享 packages/ui + packages/types + packages/api-client
一个出问题不影响其他
独立 CI/CD + 灰度发布
```

### 3.5 Feature Flag 系统（V4 P1）

```
LaunchDarkly 替代品（自建轻量版）：
  • 每个 feature 后台开关（DB system_configs 表）
  • 灰度策略：按 tenant / 角色 / 地区 / 比例
  • 一键回滚（异常时秒级关闭）

代码层封装：
  if (await featureFlag.isEnabled('agent.predict-card', { tenantId })) {
    // 新功能
  } else {
    // 旧功能
  }
```

### 3.6 AI 调用降级策略

```
主模型 → 备模型 → 兜底模型 → 拒绝（退点）

降级触发：
  • 超时 30s
  • 限流 429
  • 5xx 错误
  • 内容审核拒绝
  • 单点成本 ≥ ¥0.07（BR-901 红线）

代码层：
  ai-gateway 自动重试 1 次同模型
  失败 → 切备模型
  仍失败 → 切下一渠道（不同 provider）
  3 次失败 → 返回 AI.GATEWAY.UNAVAILABLE + 退点 + 告警
```

### 3.7 数据分层架构（ODS → DWD → DWS → ADS）

```
ODS（Operational Data Store）原始数据
  ├── 业务表（contracts / orders / users）
  ├── 抓取数据（招标公告 / 政策原文）

DWD（Data Warehouse Detail）明细
  ├── 标准化业务事件（AI 调用 / 服务订单）
  ├── 用户行为 timeline

DWS（Data Warehouse Summary）汇总
  ├── 每日 / 每周 / 每月聚合
  ├── 客户活跃度 / 智能管家业绩 / 平台 GMV

ADS（Application Data Service）应用层
  ├── 业务运营看板
  ├── 月度经营成长报告
  ├── 同行 PK 排行
  ├── AI 周报数据源

性能基线：
  ODS 查询 P95 ≤ 500ms
  DWD 查询 P95 ≤ 1s
  DWS / ADS 直接从聚合表取 P95 ≤ 200ms
```

### 3.8 可观测性 3 支柱（Logs / Metrics / Traces）

```
Logs：pino + 阿里 SLS
  • 每条日志含 traceId + tenantId + userId + module
  • 错误日志自动告警

Metrics：自定义 + 阿里云监控
  • 业务：QPS / 延迟 / 错误率 / AI 成本 / 各 provider 健康
  • 红线：BR-901 6 条指标实时监控

Traces：traceId 贯穿
  • 用户请求 → API → AI Gateway → 模型 → 缓存 → 审计 全链路
  • 24-admin-console R16 可视化查询
  • 报告右下角 traceId 可追溯
```

### 3.9 数据备份 + 灾备（V4 P1）

```
备份策略：
  • 全量：每日 03:00 + 30 天保留
  • 增量：每小时 + 7 天保留
  • OSS 跨区域复制（防单区故障）
  • 季度恢复演练

灾备策略：
  • 主 VPS 阿里云华东 1
  • 备 VPS 阿里云华北 2（一期手动切，二期自动）
  • RTO ≤ 4h / RPO ≤ 1h
  • DNS 切换 + 数据库主从切换
```

### 3.10 安全多层防护（V4 P4 / P8）

```
Layer 1 网络：阿里云 WAF + DDoS 防护
Layer 2 应用：Helmet + CORS + CSP + CSRF
Layer 3 鉴权：JWT + 2FA + 设备指纹
Layer 4 数据：4 道防线 + 4 层 WHERE + 字段级加密
Layer 5 审计：永不删除 + 6 年留存 + traceId 全链路
Layer 6 出境：sanitizer 脱敏 + 用户授权 + 季度自查
Layer 7 业务：反薅 5 维 + 黑名单 + 风控规则
```

## 五、应用红线（这 10 条 SHALL NOT）

```
1. SHALL NOT 用 Confirm-Shaming（"确定不要优惠？"羞辱用户）
2. SHALL NOT 假倒计时 / 假抢购 / 假稀缺
3. SHALL NOT 默认勾选用户没主动选的服务
4. SHALL NOT 故意藏取消 / 退订 / 申诉入口
5. SHALL NOT 用心理操纵让用户做与本意冲突的承诺
6. SHALL NOT 在政企版启用游戏化（合规要求）
7. SHALL NOT 在抽奖 / 大奖中故意设极低概率（合规）
8. SHALL NOT 隐藏 AI 输出的免责声明 + 数据源
9. SHALL NOT 让钩子输出价值低于点数成本（V4 红线 3）
10. SHALL NOT 让 AI 替代专业判断（BR-323）
```
